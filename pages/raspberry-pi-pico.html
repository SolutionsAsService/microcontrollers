Raspberry Pi Pico — RP2040

Complete reference for the original Raspberry Pi Pico development board based on the RP2040 dual-core Arm Cortex-M0+ microcontroller.

RP2040 Dual Cortex-M0+ 133 MHz 3.3V GPIO 26 GPIO 3 ADC Inputs USB

Reference Scope

This page covers the original Raspberry Pi Pico based on RP2040.

It should not be treated as a reference for the Raspberry Pi Pico 2, which uses the newer RP2350 microcontroller and has a different architecture and feature set.

The Raspberry Pi Pico is a small microcontroller development board designed around Raspberry Pi's RP2040 MCU.

It is fundamentally different from a Raspberry Pi computer such as a Raspberry Pi 4 or Raspberry Pi 5. The Pico is a microcontroller platform intended for firmware-controlled embedded applications.

Board Overview

The Raspberry Pi Pico exposes the RP2040's GPIO through two rows of castellated and through-hole-compatible pins.

The board provides 40 physical pins, including GPIO, power, ground, ADC-related connections, and system interfaces.

Important:

The 40-pin board count does not mean there are 40 GPIO pins. The standard Pico exposes 26 GPIO pins: GPIO0 through GPIO22, plus GPIO26 through GPIO28.

GPIO

The RP2040 exposes GPIO0 through GPIO29 internally, but the standard Raspberry Pi Pico board exposes GPIO0–GPIO22 and GPIO26–GPIO28.

GPIO functionality is highly flexible. Many peripheral functions can be routed to different GPIO pins using the RP2040's GPIO function selection system.

GPIO range exposed by the standard Pico:

GPIO0–GPIO22, GPIO26–GPIO28

ADC / Analog Inputs

The RP2040 contains a 12-bit ADC. The standard Pico exposes three ADC-capable GPIO pins for general-purpose analog measurement.

GPIO ADC Channel Physical Pin
GPIO26 ADC0 39
GPIO27 ADC1 37
GPIO28 ADC2 34
ADC3:

The RP2040 ADC includes an additional internal channel associated with the onboard temperature sensor. It is not exposed as a normal external GPIO analog input.

Internal Temperature Sensor

The RP2040 includes an internal temperature sensor connected to the ADC.

This sensor is intended primarily for temperature estimation and thermal monitoring rather than precision environmental measurement.

Do not treat the internal sensor as a precision thermometer.

Use an external temperature sensor when accurate environmental temperature measurement is required.

PWM

RP2040 provides hardware PWM through multiple PWM slices. PWM can be used for LEDs, motors, servos, buzzers, DAC-like output, and other timing applications.

Feature RP2040
PWM Slices 8
PWM Channels 16
GPIO Routing Flexible

PWM channel placement follows the RP2040's GPIO-to-PWM slice mapping. GPIO pairs generally share PWM slices, so applications requiring precise independent PWM configuration should account for slice sharing.

UART

The RP2040 provides two hardware UART peripherals: UART0 and UART1.

Peripheral Typical Signals Possible GPIO Examples
UART0 TX / RX GPIO0 / GPIO1, GPIO16 / GPIO17
UART1 TX / RX GPIO4 / GPIO5, GPIO8 / GPIO9
Important:

These are alternate-function mappings, not permanently dedicated UART pins. The RP2040's GPIO function system allows peripheral functions to be routed to multiple supported GPIO positions.

I2C

RP2040 provides two I2C controllers:

  • I2C1

The flexible GPIO matrix allows these interfaces to be assigned to different supported pin combinations.

SPI is especially useful for displays, RFID/NFC readers, flash devices, ADCs, DACs, sensors, and other high-speed peripherals.

Programmable I/O — PIO

One of the defining features of RP2040 is its programmable I/O subsystem.

RP2040 contains two PIO blocks. Each PIO block contains four state machines, providing eight programmable state machines total.

PIO is not ordinary GPIO.

PIO allows deterministic, programmable hardware-like I/O behavior without requiring the CPU to handle every individual signal transition.

Potential PIO Applications

  • Custom serial protocols
  • WS2812 / addressable LEDs
  • Parallel interfaces
  • Custom clocks
  • Timing-sensitive protocols
  • VGA-style output
  • Logic analyzers
  • Signal generation
  • Protocol bridges

USB Bootloader

The Raspberry Pi Pico can enter its USB mass-storage bootloader by holding the BOOTSEL button while connecting USB.

BOOTSEL

BOOTSEL places the RP2040 into its ROM-resident USB bootloader. This allows firmware to be loaded without requiring a traditional external programmer.

VSYS

VSYS is the primary system supply input to the Pico's power architecture.

It is useful when powering the board from a source other than the USB connector.

Do not treat VSYS as a GPIO or ordinary 3.3V pin.

Always verify the supply voltage and board power architecture before connecting an external source.

3V3(OUT)

The Pico provides a regulated 3.3V output from its onboard power circuitry.

This rail can be used to power suitable 3.3V peripherals, subject to the regulator's current limitations and the total system power budget.

Do not assume every 3.3V peripheral can be powered from this pin.

High-current modules such as motors, radios, LEDs, and some displays may require a separate regulator or power supply.

3V3_EN

3V3_EN controls the onboard 3.3V regulator.

Pulling this signal low disables the regulator and therefore removes the main 3.3V rail.

Power-control pin:

Do not use 3V3_EN as an ordinary GPIO.

ADC_VREF

ADC_VREF provides the reference input for the RP2040 ADC.

The reference voltage affects the relationship between ADC counts and input voltage.

ADC accuracy depends on the reference.

For precision analog measurement, consider the reference architecture and the electrical characteristics of the connected signal rather than assuming a perfect 3.3V ADC.

GPIO Interrupts

GPIO pins can be used as interrupt sources for embedded applications.

Common applications include:

  • Buttons
  • Rotary encoders
  • Motion sensors
  • NFC reader IRQ
  • Pulse counters
  • External timing signals
  • Data-ready signals
Interrupt design:

Keep interrupt handlers short and deterministic. Defer substantial processing to the main application or a task/state machine.

Dual-Core Architecture

RP2040 contains two Arm Cortex-M0+ cores.

Applications can run primarily on one core or use both cores where the software architecture benefits from parallel execution.

Potential Architecture

Core 0
├── Main application
├── Network / protocol processing
├── UI
└── State management

Core 1
├── Timing-sensitive work
├── Sensor processing
├── Protocol engine
└── Background tasks
Dual-core does not automatically mean faster.

Shared resources and synchronization must be designed carefully. A single-core architecture may be simpler and more reliable for many projects.

PIO state machines can perform deterministic I/O operations independently of the CPU cores.

Onboard LED

The standard Raspberry Pi Pico includes an onboard user LED.

On the original Pico hardware, the LED is controlled through the board's USB-related interface rather than simply being treated as a normal RP2040 GPIO connection.

Board-specific behavior:

Do not assume the onboard LED corresponds to a normal exposed GPIO in the same way it does on many Arduino boards.

Reset / RUN

The Pico exposes the RP2040 RUN control signal.

Pulling RUN low resets the RP2040.

RUN

RUN is useful when integrating the Pico into external hardware that needs hardware-controlled reset behavior.

Debugging

RP2040 supports SWD debugging.

Typical Debug Signals

  • SWCLK
  • SWDIO
  • GND

Debugging can be performed using compatible SWD debug hardware and development tools.

Button Example

A button can be connected between a GPIO and ground while using the internal pull-up resistor. 

const int BUTTON_PIN = 10;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
}

void loop() {

  if (digitalRead(BUTTON_PIN) == LOW) {
    // Button pressed
  }

}
Logic:

With an internal pull-up, the normal state is HIGH and the pressed state is LOW.

Analog Sensor Example

const int SENSOR_PIN = A0;

void setup() {
  Serial.begin(115200);
}

void loop() {

  int value = analogRead(SENSOR_PIN);

  Serial.println(value);

  delay(100);
}

On Arduino-style RP2040 environments, analog pin aliases such as A0, A1, and A2 commonly correspond to GPIO26, GPIO27, and GPIO28.

What the Pico Is Not

The Raspberry Pi Pico is not a Linux computer.

It does not normally run Raspberry Pi OS, Debian, Ubuntu, or other desktop/server operating systems.

It is intended for deterministic embedded control rather than general-purpose desktop computing.

Pico W

Raspberry Pi also produces the Pico W, which adds wireless networking hardware to the Pico family.

Do not merge Pico and Pico W hardware definitions.

The basic RP2040 GPIO architecture remains important, but wireless hardware introduces additional board-level considerations.

Flash and Boot Architecture

The standard Pico uses external QSPI flash for application firmware and persistent program storage.

The RP2040's ROM contains the low-level boot functionality required to enter the USB bootloader. 

RP2040 ROM
    │
    ├── Normal boot
    │       ↓
    │   External QSPI Flash
    │       ↓
    │   Application Firmware
    │
    └── BOOTSEL
            ↓
        USB Bootloader
            ↓
        Firmware Upload

QSPI Flash

The external flash used by the standard Pico is connected to the RP2040 through its dedicated QSPI interface.

Reserved hardware:

QSPI-connected pins are not intended to be treated as normal user GPIO on the standard Pico.

Engineering Rules

  1. Treat Pico GPIO as 3.3V logic.
  2. Do not apply 5V directly to GPIO.
  3. Verify the voltage requirements of every peripheral.
  4. Keep motor and high-current loads away from MCU power rails unless the power budget explicitly supports them.
  5. Use appropriate pull-ups for I2C.
  6. Account for SPI chip-select requirements when sharing a bus.
  7. Verify alternate-function assignments before finalizing a PCB.
  8. Account for PWM slice sharing.
  9. Use ADC-capable GPIO only for external analog inputs.
  10. Keep analog signals away from unnecessary digital noise.
  11. Use PIO when deterministic custom I/O is required.
  12. Do not use reserved flash connections as normal GPIO.
  13. Treat BOOTSEL and RUN as system functions rather than ordinary application inputs.
  14. Verify the exact Pico hardware revision before designing a PCB around board-specific behavior.

Practical Pin Selection

Good Candidates for Digital Inputs

Most exposed GPIO can be used for ordinary digital inputs.

Good Candidates for Analog Inputs

GPIO26, GPIO27, and GPIO28.

Good Candidates for I2C

GPIO4 / GPIO5 are a common convenient arrangement, although other valid mappings exist.

Good Candidates for SPI

GPIO16–19 are a commonly used SPI arrangement.

Use PIO When

  • A peripheral uses a non-standard protocol.
  • Precise timing is required.
  • CPU-driven bit banging is undesirable.
  • A custom serial protocol must be implemented.

Troubleshooting

Pico Does Not Appear Over USB

  • Check USB cable.
  • Try BOOTSEL mode.
  • Verify firmware image.
  • Check USB power.
  • Try another USB port.

OLED Does Not Work

  • Check VCC.
  • Check GND.
  • Verify SDA/SCL.
  • Verify I2C address.
  • Check pull-ups.
  • Confirm the display controller.

SPI Device Does Not Respond

  • Check SCK.
  • Check MOSI.
  • Check MISO.
  • Check CS.
  • Verify SPI mode.
  • Check voltage levels.
  • Verify device reset state.

ADC Values Look Wrong

  • Verify the input voltage range.
  • Verify ADC reference assumptions.
  • Check grounding.
  • Reduce digital noise.
  • Verify ADC pin selection.
