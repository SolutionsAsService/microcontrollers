LCD & OLED Displays

A practical reference for connecting character LCDs, graphical LCDs, OLED displays, and common display controller interfaces to Arduino, ESP32, and other microcontrollers.

LCD OLED I2C SPI Parallel SSD1306

Quick Reference

16×2 Character LCD

Typically uses the HD44780-compatible interface and can operate using either 4-bit or 8-bit parallel communication.

20×4 Character LCD

Larger HD44780-compatible character display commonly used for instrumentation and embedded control panels.

0.96″ OLED

Small graphical display commonly based on the SSD1306 controller, usually using I2C or SPI.

1.3″ OLED

Larger monochrome OLED modules commonly using SSD1306 or SH1106-compatible controllers.

LCD — Liquid Crystal Display

LCDs use liquid crystals to control the passage of light through the display. Character LCD modules are especially common in microcontroller projects because they are inexpensive, robust, and supported by many libraries.

The classic embedded character LCD is based around the HD44780-compatible interface.

Important: Character LCD modules and graphical LCD modules are not necessarily electrically or software compatible. Always identify the controller and interface before wiring a display.

16×2 LCD Pin Configuration

A standard 16×2 character LCD commonly exposes 16 pins. Pins D0–D7 form the parallel data bus while RS, RW, and EN control communication.

Pin Name Type Function Typical Connection
1 VSS Power Ground GND
2 VDD / VCC Power LCD supply voltage Usually 5V
3 V0 / VEE Analog Contrast adjustment Potentiometer / contrast circuit
4 RS Input Register Select MCU GPIO
5 RW Input Read / Write selection GND for write-only operation
6 EN Input Enable / latch control MCU GPIO
7 D0 Data Data bit 0 MCU GPIO
8 D1 Data Data bit 1 MCU GPIO
9 D2 Data Data bit 2 MCU GPIO
10 D3 Data Data bit 3 MCU GPIO
11 D4 Data Data bit 4 MCU GPIO
12 D5 Data Data bit 5 MCU GPIO
13 D6 Data Data bit 6 MCU GPIO
14 D7 Data Data bit 7 MCU GPIO
15 A / LED+ Power Backlight anode Backlight supply
16 K / LED− Power Backlight cathode GND

LCD 4-Bit Mode

Most Arduino projects do not need all eight LCD data lines. In 4-bit mode, only D4–D7 are used for data transfer.

Typical Wiring

LCD Microcontroller
RS GPIO
RW GND
EN GPIO
D4 GPIO
D5 GPIO
D6 GPIO
D7 GPIO

This reduces the required data/control GPIO count to approximately six pins.

I2C LCD Backpack

Many character LCDs are fitted with an I2C backpack based on an I/O expander such as the PCF8574 family. This converts the parallel LCD interface into a two-wire I2C connection.

LCD Backpack MCU Interface Purpose
GND GND Ground
VCC 5V / compatible supply Power
SDA I2C SDA Data
SCL I2C SCL Clock
Voltage warning: Many inexpensive I2C LCD backpacks are designed around 5V systems. When connecting one to a 3.3V-only MCU such as many ESP32 boards, verify the backpack's pull-up configuration and voltage compatibility.

OLED — Organic Light-Emitting Diode

OLED displays contain pixels that emit their own light. Unlike conventional LCDs, an OLED does not require a separate backlight to illuminate the image.

Small monochrome OLED modules are particularly popular in embedded systems because they provide graphics, text, icons, sensor values, status information, and simple user interfaces with very few MCU pins.

SSD1306

One of the most common controller families found in small monochrome OLED modules.

SH1106

Another common monochrome OLED controller found in approximately 1.3-inch modules.

I2C

Requires only SDA and SCL for communication, making it convenient for compact embedded projects.

SPI

Uses additional signals but can provide faster display transfers depending on the controller and implementation.

Typical I2C OLED Pinout

A common four-pin OLED module exposes power and the two I2C communication lines.

Pin Name Function MCU Connection
1 GND Ground GND
2 VCC Power Compatible 3.3V / 5V supply
3 SCL I2C clock MCU SCL
4 SDA I2C data MCU SDA

ESP32 + I2C OLED

A common ESP32 arrangement uses GPIO21 for SDA and GPIO22 for SCL, although the ESP32 GPIO matrix allows peripherals to be routed to other suitable GPIOs.

Common ESP32 Wiring

OLED ESP32
GND GND
VCC 3.3V or module-compatible supply
SDA GPIO21
SCL GPIO22
Important: GPIO21/22 are common ESP32 defaults, not universal hardware requirements. Check your specific board and firmware configuration.

Arduino Nano + I2C OLED

On the classic ATmega328P Arduino Nano, I2C is provided through A4 and A5.

OLED Arduino Nano
GND GND
VCC Compatible supply
SDA A4
SCL A5

Common OLED I2C Addresses

OLED modules frequently use one of a small number of I2C addresses. The exact address depends on the controller and board configuration.

Address Common Usage
0x3C Very common SSD1306 OLED address
0x3D Common alternate OLED address
Do not assume the address. If the display does not respond, use an I2C scanner or verify the module documentation and address-selection hardware.

SPI OLED

Some OLED modules use SPI rather than I2C. SPI generally requires more connections but can provide higher communication throughput.

GND Ground
SCLK / CLK SPI clock
MOSI / DIN Display data
CS Chip Select
DC Data / Command selection
RST / RES Display reset

Display Interface Types

Parallel

Multiple GPIO lines transfer data directly to the display. Common with HD44780-compatible character LCDs.

I2C

Two communication wires: SDA and SCL. Excellent when GPIO availability is limited.

SPI

Uses clock, data, chip select and often command/reset lines. Useful for faster graphical display updates.

UART

Some intelligent displays expose a serial interface and implement graphics or commands internally.

Arduino OLED Example

A typical SSD1306 I2C display can be driven using a graphics library such as Adafruit SSD1306 together with Adafruit GFX. 

#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

#define SCREEN_WIDTH 128
#define SCREEN_HEIGHT 64

#define OLED_RESET -1
#define OLED_ADDRESS 0x3C

Adafruit_SSD1306 display(
  SCREEN_WIDTH,
  SCREEN_HEIGHT,
  &Wire,
  OLED_RESET
);

void setup() {

  Serial.begin(115200);

  if (!display.begin(
        SSD1306_SWITCHCAPVCC,
        OLED_ADDRESS
      )) {

    Serial.println("OLED initialization failed");

    while (true) {
      delay(1000);
    }
  }

  display.clearDisplay();

  display.setTextSize(1);
  display.setTextColor(SSD1306_WHITE);

  display.setCursor(0, 0);
  display.println("ESP/Arduino Lab");

  display.setCursor(0, 16);
  display.println("OLED ONLINE");

  display.display();
}

void loop() {

}

Common OLED Operations

Operation Purpose
clearDisplay() Clears the graphics buffer
setCursor() Sets text position
setTextSize() Changes text scale
setTextColor() Sets text rendering color
print() Writes text without automatically adding a newline
println() Writes text and advances to a new line
display() Transfers the graphics buffer to the physical display

Operation Purpose
lcd.begin(cols, rows) Initializes the LCD dimensions

lcd.print() Writes characters
lcd.home() Moves cursor to the home position

Power & Voltage Considerations

CAUTION

Check VCC

Never assume that every display module accepts both 3.3V and 5V. Verify the actual module specifications.

CAUTION

Check Logic Levels

A display can have a supply voltage that differs from its required digital logic voltage.

CAUTION

Check Pull-Ups

I2C requires pull-up resistors. Some display modules include them already.

CAUTION

Backlight Current

Character LCD backlights can draw significantly more current than the controller logic.

Engineering Rules

  • Identify the controller. SSD1306, SH1106 and HD44780-compatible modules are different devices.
  • Identify the interface. Determine whether the display uses I2C, SPI, parallel, UART, or another interface.
  • Verify voltage. Check both supply voltage and digital logic levels.
  • Verify the I2C address. Do not assume every OLED is 0x3C.
  • Do not power displays from arbitrary GPIO pins. Use the board's appropriate power rail unless the current requirements are explicitly within GPIO limits.
  • Keep grounds common. The MCU and display normally need a shared reference.
  • Consider bus conflicts. Multiple I2C devices can share SDA/SCL, but address conflicts must be resolved.
  • Consider refresh rate. Continuously redrawing an entire graphical display can consume significant bus bandwidth and processing time.

Typical Embedded Applications

Sensor Monitor

Temperature, humidity, pressure, voltage, current and other telemetry can be displayed locally.

Network Monitor

Display IP addresses, Wi-Fi status, RSSI, connection state, packet counters and other network information.

Hardware Controller

Combine a display with buttons, encoders, switches or touch input to create a local control interface.

Diagnostics

Show boot state, firmware version, error codes, sensor values, power information and system status.
